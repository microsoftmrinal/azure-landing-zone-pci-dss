Customer requirements

Windows IIS VMs in North Europe and West Europe

Virtual machines only. One Trusted Launch VM per region, no public IP, behind an internal load balancer and Private Link Service.

Implemented

IIS on port 8082 with an SSL FQDN

HTTPS on TCP 8082 end to end; Front Door checks the certificate name against the application FQDN.

Implemented

Certificate and IIS binding

The site, the 8082 HTTPS binding and the certificate for the FQDN are deployed by the application pipeline.

Operational

Public internet clients

Front Door Premium + WAF is the only public web entry and reaches the VMs over Private Link. It does not pass through the firewall.

Implemented

Client B: inbound over VPN

VPN Gateway, then Firewall Premium, then IIS on 8082 only, from approved Client B prefixes.

Implemented

Client A: outbound from the VM

Scoped firewall egress rule; the reserved pip-clientA-nat-egress can be attached to the firewall. Client A must allow-list all firewall egress IPs.

Implemented

Single fixed Client A source IP

Azure Firewall does not pin a destination to one of its IPs. A fixed address needs a separately approved NAT Gateway design.

Operational

App connects to Managed HSM

Private endpoint, private DNS and managed identity with HSM RBAC. No internet path.

Implemented

NEU origin fails: use WEU

Front Door health probes: NEU priority 1, WEU priority 2. New requests move; in-flight requests do not.

Implemented

NEU VPN or VM fails: VPN clients

A gateway and firewall exist in both regions. Moving VPN clients to the WEU VM needs a private DNS name repointed to the WEU load balancer.

Operational

App starts work in WEU if NEU is down

The app is installed in both regions. Only one region may process at a time (lease with fencing, idempotent payments).
